# 결정 기록

결정마다 무엇을 골랐고, 무엇을 버렸고, 왜 그랬는지를 남긴다. 뒤집으면 지우지 않고 새 줄로 남긴다.

| # | 날짜 | 결정 | 버린 대안 | 이유 |
|---|---|---|---|---|
| D01 | 2026-11-20 | apt-search와 다른 저장소로 시작 | apt-search에 붙이기 | 실거래가 검색과 법령 질의응답은 데이터·평가가 전혀 다름 |
| D02 | 2026-11-20 | 원문(data/raw)과 처리 결과(data/processed) 분리 | 받으면서 바로 쪼개기 | 쪼개는 방식을 바꿔도 API를 다시 부르지 않음 |
| D03 | 2026-11-20 | 조 단위·항 단위 두 가지를 모두 만들어 비교 | 하나만 정하기 | 어느 쪽이 나은지는 정답지로 재서 정함 (실험 1) |
| D04 | 2026-11-20 | 삭제된 항, 번호만 남은 조문은 검색 대상에서 뺌 | 그대로 두기 | 내용 없는 덩어리가 검색 결과를 차지함 (시행령 제2조의2 → 제9조 이동 사례) |
| D05 | 2026-11-20 | 화면은 채팅 형태, Streamlit | 웹 프레임워크 따로 (React 등) | 화면까지 Python으로 짜고, 검색 결과를 눈으로 보면서 개발 |
| D06 | 2026-11-20 | 화면을 검색보다 먼저 만듦 | 검색 실험 끝나고 화면 | 본인 요청: 화면을 보면서 개발하는 게 낫다 |
| D07 | 2026-11-20 | 첫 검색은 BM25를 Python으로 직접 구현 (글자 두 개 단위) | apt-search의 Elasticsearch + Nori 재사용 | 다른 프로젝트 의존을 없애고, 점수 계산을 직접 설명할 수 있게. Elasticsearch는 필요해지면 이 저장소에 따로 구성해 비교 |
| D08 | 2026-11-20 | 패키지는 프로젝트 가상환경(.venv)에 설치, 목록은 requirements.txt | 컴퓨터 전체에 설치 | 다른 프로젝트와 섞이지 않고 같은 환경을 다시 만들 수 있음 |
| D09 | 2026-11-20 | 질문의 일상어는 법률 용어를 **덧붙이고**(바꾸지 않음), 금액·날짜는 검색어에서 뺌 | 일상어를 법률 용어로 바꾸기 / 그대로 두기 | 바꾸면 원래 말로 맞던 조문을 잃음. 숫자는 검색에는 방해, 계산 단계에서 씀 |
| D10 | 2026-11-20 | 일상어 사전 항목마다 출처(실무/화면 테스트)를 적고, 정답지 질문의 단어로 사전을 늘리지 않음 | 틀린 평가 문항마다 사전 추가 | 평가 점수에 맞춘 사전은 실제 질문에서 효과가 없음 (과적합). `확정일자` 항목은 출처 없는 추측이었고 T05를 틀리게 해서 뺌 |
