# 설계·일정

## 목표

1. 부동산 법령을 **직접 짠 Python 파이프라인**으로 수집·파싱·색인·갱신한다.
2. 실무에서 실제로 받던 질문으로 **정답지**를 만들고, 그 정답지로 검색·답변을 숫자로 평가한다.
3. 쪼개는 단위, 검색 방식, 역할 반영 방식을 바꿔 가며 **같은 기준으로 비교**하고, 틀린 답을 원인별로 나눈다.

"만들었다"보다 "어떻게 재고, 무엇을 보고 바꿨는가"가 결과물이다.

## 법령 범위

| 단계 | 법령 | 역할 |
|---|---|---|
| 1차 | 주택임대차보호법 + 시행령 | 임차인·임대인 |
| 1차 | 민간임대주택에 관한 특별법 + 시행령 | 임대인·임차인·시행사 |
| 1차 | 공인중개사법 + 시행령·시행규칙 | 임차인·임대인 |
| 2차 | 주택법 + 시행령 | 시행사 |
| 2차 | 공동주택관리법 + 시행령 | 시공사·임차인 |
| 2차 | 건설산업기본법 | 시공사 |

| 2차 | 국토의 계획 및 이용에 관한 법률 + 시행령 | 시행사 |
| 3차 | 시·도 도시계획 조례 (자치법규) | 시행사 |
| 범위 밖 | 세법(조세특례제한법·지방세특례제한법 등), 판례, 보증기관 규정 | 질문이 오면 "범위 밖" 안내 |

1차로 파이프라인과 평가를 끝까지 돌린 뒤 2차를 붙인다. 범위를 넓히는 것보다 1차를 끝까지 재는 게 먼저다.

## 실무에서 막혔던 것 (정답지·도구 설계의 출발점, 본인 경험 2026-11-20)

- 사업계획서를 만들 때 이 땅이 어느 조례에 해당하는지 몰랐다 → 법·시행령은 범위만 정하고 실제 건폐율·용적률은 조례에 있다
- 다가구·다주택 임차인이 보증보험 가입, 전입신고를 물어 왔다 → 일부 답은 법령이 아니라 판례·보증기관 규정에 있다
- 임대사업자로 등록한 임대인에게는 적용되는 법이 많았고 세금은 잘 몰랐다
- 보증금↔월세 전환율을 매번 확인해야 했다 → 조문만으로는 숫자가 안 나오고 그날 기준금리가 필요하다

## 목표 사용 장면 (본인 지정, 2026-11-20)

> "나 2025년 3월 1일 계약인데 갱신 가능?"처럼 **자기 상황을 말하면 결론을 답해 주는 것**.
> 조문을 찾아 주는 것(korean-law-mcp가 이미 잘함)에서 멈추지 않고, 상황 정리 → 빠진 정보 되묻기 → 조문 검색 → 날짜·금액 계산 → 결론과 근거를 함께 답한다.

| 단계 | 하는 일 |
|---|---|
| 상황 정리 | 계약일·기간·갱신 이력·등록 임대주택 여부·보증금/월세 추출 |
| 되묻기 | 결론에 꼭 필요한데 빠진 정보만 묻기 (예: 이미 갱신한 적 있는지) |
| 검색 | 근거 조문 |
| 계산 | 만료일, 갱신요구 가능 기간(6개월~2개월 전), 증액 상한, 전환율 |
| 답변 | 결론 + 계산 과정 + 근거 조문 + 경계에 걸리면 확정하지 않음 |

평가 유형 `사례·날짜 계산`(C로 시작하는 문항)은 결론이 맞는지, 되물어야 할 때 되물었는지를 따로 채점한다.

## 단계: RAG → 도구를 쓰는 Agent

| 단계 | 하는 일 | 답할 수 있게 되는 질문 |
|---|---|---|
| 1단계 RAG | 질문 → 근거 조문 검색 → 인용 답변 | 조문만으로 답이 나오는 질문 |
| 2단계 도구 | 기준금리 조회 + 전환율 계산 / 필지 용도지역 조회 → 해당 조례 조문 검색 | "오늘 전환율 상한", "이 땅 용적률" |
| 판단 기준 | 언제 조문만 답하고, 언제 도구를 부르고, 언제 "법령 밖"이라고 말할지 | 평가 유형 `계산·외부 데이터`, `조례·외부 데이터`, `법령 밖 근거`, `거절` |

- 필지 용도지역 조회용 공공 API(토지이용계획 계열)와 자치법규 API 제공 범위는 1주차에 확인한다.
- 2단계 평가는 "도구를 불러야 할 때 불렀는가"와 "숫자가 맞는가"를 따로 잰다.

## 파이프라인 설계 포인트

| 결정 | 이유 |
|---|---|
| 원문(raw)과 처리 결과 분리 | 파싱·쪼개기를 바꿔도 API를 다시 부르지 않음 (apt-search와 같은 원칙) |
| 법령 ID + 시행일자로 버전 보관 | 개정 전 조문을 인용하는 실수를 잡으려면 어느 시점 조문인지 남아 있어야 함 |
| 조문 고유 ID (법령·조·항·호) | 같은 조문을 다시 넣어도 중복 없음, 평가 때 정답 조문과 바로 비교 |
| 시행령 위임 연결 | "대통령령으로 정하는" 부분은 시행령 조문까지 따라가야 답이 완성됨 (전월세 전환율 등) |
| 갱신은 바뀐 법령만 | 시행일자를 비교해 달라진 법령만 다시 파싱·색인 |
| 근거 없으면 답하지 않음 | 법령에 없는 질문(시세, 개별 분쟁 판단)에는 "법령으로 답할 수 없음" |

## 실험 (같은 정답지로 비교)

1. **쪼개는 단위**: 조 단위 vs 항 단위 vs 항 + 조 제목 붙이기
2. **검색 방식**: BM25만 / 벡터만 / 하이브리드(RRF)
   - 법은 "제6조의3", "계약갱신요구권"처럼 정확한 번호·용어 일치가 중요해서 BM25가 강할 것으로 예상 → 실제로 확인
3. **역할 반영 방식**: (A) 역할 무시 (B) 역할로 법령 필터 (C) 역할로 가중치만
   - 예상: (B)는 정확도가 오르지만 법령을 넘나드는 질문(등록 임대주택 임차인 등)을 놓친다 → 숫자로 확인
4. **시행령 연결**: 연결 없음 vs 위임 조문 함께 검색

5. **기준선 비교 — korean-law-mcp** (github.com/chrisryugj/korean-law-mcp, MIT, 2026-11 기준 별 2,900여 개)
   - 법제처 API 42개를 도구 10개로 묶은 MCP 서버. 법령·판례·조례 조회와 인용 검증까지 이미 잘 한다.
   - 같은 정답지로 (A) LLM + korean-law-mcp, (B) 이 프로젝트의 역할별 RAG, (C) 둘을 합친 것을 비교한다.
   - 확인할 가설: 법제처 검색은 법령명·키워드 중심이라 "집주인이 실거주한다며 나가래요" 같은 일상어 질문에서 맞는 조문을 덜 찾을 것. 반대로 조회 범위(판례·조례)는 MCP가 넓다.
   - 결과가 MCP 쪽이 낫다면 조회는 MCP에 맡기고, 이 프로젝트는 역할 판단·계산·범위 밖 거절에 집중한다.

## 제조 이식 실험 (4주차)

- 부동산에서 세운 파이프라인·평가 방식을 제조 안전 법령(산업안전보건법 등)에 그대로 옮긴다.
- 제조는 본인이 정답을 판별할 수 없으므로 **정부 공식 해석례(질의·회신)를 정답지로** 쓴다. 해석례가 공개 API로 충분히 나오는지 1주차에 확인.
- 보여 줄 것: 무엇이 그대로 통했고 무엇을 바꿔야 했는가 (쪼개는 단위, 별표·고시 처리, 용어 차이 등).

## 평가 지표

| 지표 | 뜻 |
|---|---|
| 조문 재현율@5 | 정답 조문이 검색 상위 5개 안에 들어온 비율 |
| 인용 정확도 | 답변이 인용한 조문 중 정답 조문 비율 |
| 핵심 포인트 포함률 | 정답지의 핵심 내용(숫자·조건)이 답변에 들어간 비율 |
| 거절 정확도 | 법령으로 답할 수 없는 질문에 답하지 않은 비율 |

실패 사례는 하나씩 열어 원인별로 분류한다: 시행령에 있는 걸 법에서 찾음 / 다른 법령 조문 / 개정 전 조문 / 숫자 틀림 / 근거 없이 답함.

## 주의

- 법률 자문 아님 안내를 답변마다 붙인다.
- AI 코딩 도구를 써도 되지만, 쪼개기·검색·평가 코드는 직접 설명할 수 있어야 한다 (기술 인터뷰 손코딩 대비).
- 정답지의 근거 조문은 **수집한 원문과 대조해 확정**한다. 기억이나 블로그 글로 정답을 정하지 않는다.
