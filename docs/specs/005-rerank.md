# 005 리랭커 (검색 결과 다시 판단하기)

## 목적
1차 검색(하이브리드)은 빠르지만 거칠다. 예: 월세 인상 질문에서 정답 제7조가 11위 (E02). 상위 20개를 질문과 조문을 **한 쌍씩 함께 읽는** 모델로 다시 점수 매겨, 정답이 5위 안으로 올라오게 한다.

## 입력·출력
- 입력: 질문, 1차 검색 후보 20개
- 출력: 다시 매긴 순서의 상위 5개 (리랭커 점수)

## 동작 규칙
- 모델: `BAAI/bge-reranker-v2-m3` (다국어, 무료, 노트북 GPU에서 실행). 외부 API 안 씀
- 1차 후보: 하이브리드 상위 20개 (`CANDIDATES = 20`)
- 리랭커에는 원래 질문 + `text_with_title`을 넣음
- 임베딩(같은 표현으로 따로 계산해 비교)과 다르게, 질문과 조문을 함께 넣어 판단 → 느리지만 정확. 그래서 후보 20개에만 적용

## 하지 않는 것
- LLM으로 판단하기 (답변 단계에서)
- 후보 수 조정 실험 (결과 보고 결정)

## 확인 방법
- `python src/evaluate.py` 표에 `hybrid+rerank` 줄 추가 → hybrid와 비교
- 1차 상위 20개 안에 정답이 아예 없는 문항은 리랭커로도 못 살림 → "후보 재현율@20"도 같이 출력해 원인을 나눔
- 질문 하나당 걸린 시간 기록

## 결과
2026-11-20 조 단위 hybrid 0.895 → rerank 0.877로 오히려 낮아짐 (C02·C04 새로 놓침). 후보 재현율@20은 0.951이라 후보는 충분함. 원래 질문을 넣은 것이 원인 후보 → 다듬은 질문으로 다시 비교할 것. 항 단위 기준 질문당 0.32초. 자세히 → [EXPERIMENTS.md E03](../EXPERIMENTS.md)
